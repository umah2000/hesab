# به‌روزرسانی نصب مشتری (Migration امن)

## خلاصه
```powershell
# بسته‌ی نسخه‌ی جدید را باز کنید؛ PowerShell با دسترسی Administrator؛ ترجیحاً بعد از ساعت کاری
powershell -ExecutionPolicy Bypass -File .\deploy\windows\upgrade.ps1
```
صندوق‌هایی که Device Agent دارند در این چند دقیقه **آفلاین می‌فروشند** و بعد همگام می‌شوند (ADR-0017). صندوق‌هایی که فقط مرورگر دارند، تا پایان به‌روزرسانی نمی‌فروشند.

## مراحل و ضمانت‌ها
1. **نصب کنار نسخه‌ی قبلی:** فایل‌های نسخه‌ی جدید در `releases\<نسخه>` نصب می‌شوند، در حالی که نسخه‌ی قبلی هنوز کار می‌کند.
2. **توقف سرور.**
3. **`flask upgrade`** از نسخه‌ی جدید:
   1. **بررسی استفاده:** اگر در ۳ دقیقه‌ی اخیر نشست، اپ یا صندوقی فعال بوده، اجرای دستی متوقف می‌شود (اسکریپت پس از توقف سرور خودش `--force` می‌دهد).
   2. **پشتیبان پیش از هر تغییر:** پشتیبان بررسی‌شده و کپی رمزنگاری‌شده‌ی آن گرفته می‌شود. اگر ناموفق باشد، **هیچ تغییری** داده نمی‌شود.
   3. **همه‌ی migrationها در یک تراکنش:**
      - DDL در SQL Server تراکنشی است.
      - شکست یعنی برگشت **کامل** دیتابیس به نسخه‌ی قبل.
      - این رفتار با یک migration خراب عمدی آزموده شده است (`tests/test_upgrade.py`): دو migration موفق قبلی هم برگشت خوردند و نسخه‌ی قدیمی روی همان دیتابیس کار کرد.
   4. **همگام‌سازی:** مجوزها و داده‌های پایه به‌روز می‌شوند.
   5. **بررسی سلامت:**
      - ساختار در آخرین نسخه است؛
      - یک سازمان وجود دارد؛
      - همه‌ی اسناد قطعی تراز هستند؛
      - موجودی با گردش انبار برابر است.
4. **نتیجه:**

   | نتیجه | اقدام اسکریپت |
   |---|---|
   | موفق | `current` به نسخه‌ی جدید اشاره می‌کند و سرور اجرا می‌شود؛ سه نسخه‌ی آخر نگه داشته می‌شوند |
   | کد ۱ — دیتابیس تغییری نکرده یا کامل برگشت خورده | نسخه‌ی قبلی دوباره اجرا می‌شود |
   | کد ۲ — بررسی سلامت ناموفق | نسخه‌ی جدید اجرا می‌شود و هشدار نمایش داده می‌شود؛ با پشتیبانی تماس بگیرید |
   | کد ۳ — نسخه‌ی جدید پاسخ نمی‌دهد | دیتابیس به‌روز شده است: گزارش `server.log` را بررسی کنید. در صورت نیاز از پشتیبانِ پیش از به‌روزرسانی بازیابی کنید (پایین) |

## فرمان‌های مفید (در `C:\nextcam\config`)
```powershell
$py = "C:\nextcam\current\backend\.venv\Scripts\python.exe"
& $py -m flask --app app version           # نسخه‌ی برنامه و دیتابیس
& $py -m flask --app app check-integrity   # بررسی سلامت در هر زمان
```
نسخه در «تنظیمات» هم از `GET /api/v1/system/version` خوانده می‌شود.

## بازگشت کامل (فقط در حالت کد ۳ و با نظر پشتیبانی)
1. سرور را متوقف کنید: `Stop-ScheduledTask "NEXTCAM Server"`.
2. پشتیبانِ پیش از به‌روزرسانی را بازیابی کنید. نام آن در خروجی `upgrade` و تاریخچه‌ی پشتیبان‌گیری آمده است.
   - کپی رمزنگاری‌شده با `python -m app.modules.system.backup_crypto decrypt` باز می‌شود.
   - سپس `RESTORE DATABASE ... WITH REPLACE` در SSMS.
3. `current` را به پوشه‌ی نسخه‌ی قبلی برگردانید:
   ```powershell
   cmd /c rmdir C:\nextcam\current
   cmd /c mklink /J C:\nextcam\current C:\nextcam\releases\<نسخه‌ی قبلی>
   ```
   سپس `Start-ScheduledTask "NEXTCAM Server"`.

> ⚠️ فروش‌هایی که پس از به‌روزرسانی ثبت شده‌اند، با این بازیابی از بین می‌روند. فروش‌های آفلاین هنوز همگام‌نشده‌ی صندوق‌ها در صف Agent می‌مانند و پس از بازیابی دوباره ارسال می‌شوند.

## مجوز
- اگر «پشتیبانی تا» در مجوز، پیش از تاریخ انتشار نسخه‌ی جدید باشد، `upgrade` هشدار می‌دهد ولی متوقف نمی‌شود (Q25).

## برای تیم توسعه: ساخت نسخه
1. `backend/app/version.py` (`VERSION`، `RELEASED`) و `backend/pyproject.toml` را هم‌زمان افزایش دهید. سازنده‌ی بسته ناهمخوانی را رد می‌کند.
2. CI سبز.
3. `python tools/release/build_release.py --out dist --build-frontend --wheels`
4. فایل zip و `.sha256` را منتشر کنید.
