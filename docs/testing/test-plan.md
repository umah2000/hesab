قاعده: هیچ تستی موفق گزارش نمی‌شود مگر اجرا شده باشد. تست Mock جایگزین تست دستگاه واقعی نیست.

## ۲. تست‌های مالی کلیدی
- سند نامتوازن قطعی نمی‌شود؛ سند قطعی ویرایش/حذف نمی‌شود؛ برگشت = معکوس دقیق.
- فاکتور قطعی ← سند متوازن + گردش انبار + بهای تمام‌شده صحیح (مقایسه با محاسبه دستی).
- پرداخت ترکیبی (نقد + کارت + نسیه) ← جمع = مبلغ فاکتور.
- همان Idempotency-Key دو بار ← یک فاکتور، یک سند.
- دو صندوق هم‌زمان روی یک کالا ← موجودی و میانگین صحیح، بدون deadlock (تست هم‌روندی).
- میانگین موزون: جدول سناریوهای عددی شامل موجودی صفر و منفی.
- گرد کردن: جمع ردیف‌ها = جمع فاکتور.
- بستن شیفت: کسری/اضافه ← سند صحیح.
- تراز آزمایشی = جمع اسناد قطعی.

## ۴. امنیت
- دسترسی بدون مجوز و بین شعب برای همه endpointها (تست پارامتری خودکار از روی جدول مجوزها).
- Brute force روی ورود ← قفل و Rate limit.
- CSRF: درخواست تغییردهنده بدون توکن ← 403.
- پاسخ خطای 500 شامل stack trace یا جزئیات داخلی نیست (✅ تست موجود: `test_unhandled_error_hides_internals`).
- Agent: درخواست از Origin غیرمجاز، Host غیر localhost (DNS rebinding)، بدون توکن ← رد.
- لاگ‌ها: جست‌وجوی خودکار الگوی PAN/رمز در خروجی تست‌ها.
- Mock کارت‌خوان در production فعال نمی‌شود (✅ تست موجود: `test_mock_terminal_forbidden_in_production`).

## ۵. وضعیت فعلی (پایان فاز ۴)
- Backend: ۹۱ تست روی SQL Server 2019، همه موفق. علاوه بر فاز ۳:
  - فروش نقدی: مبالغ، مالیات کالای مشمول و معاف، سند حسابداری با حساب‌های درست، کاهش موجودی و شماره پیوسته.
  - قیمت‌گذاری در سرور: مقدار دستکاری‌شده‌ی برچسب ترازو نادیده گرفته می‌شود؛ قیمت بسته = ضریب × قیمت پایه؛ رد مقدار اعشاری برای کالای عددی؛ تنظیم «قیمت بدون مالیات».
  - پروموشن، تخفیف بالاتر از سقف: رد بدون تأیید، رد رمز نادرست، رد تأیید خود صندوق‌دار، تأیید یک‌بارمصرف.
  - ممیزی حذف کالای اسکن‌شده و نیاز صندوق‌دار به تأیید.
  - پرداخت: عدم تطابق مبلغ، کارت بدون شماره پیگیری، پرداخت ترکیبی، نسیه با سقف اعتبار و بدون مشتری، مجوز روش‌های پرداخت.
  - Idempotency ثبت فاکتور و **رد تغییر یا حذف فاکتور قطعی، ردیف‌ها و پرداخت‌ها در خود دیتابیس**.
  - سیاست موجودی منفی (هشدار و رد).
  - تعلیق و بازیابی بین صندوق‌ها.
  - شیفت: یک شیفت باز برای هر صندوق و کاربر، کسری با سند، و گزارش.
  - برگشت: مبالغ نسبی، بهای تمام‌شده‌ی اصلی پس از تغییر میانگین، رد بیش از باقی‌مانده، تعیین مبلغ استرداد توسط سرور.
  - کارت‌خوان Mock: timeout ← نامشخص ← مسدود شدن پرداخت دوباره ← استعلام ← تأیید؛ تطبیق دستی؛ عدم بستن شیفت با تراکنش نامشخص.
  - **۷ صندوق هم‌زمان:** فروش بیش از موجودی رخ نمی‌دهد و شماره‌ها ۱ تا ۲۵ بدون فاصله‌اند.
  - **روز کاری کامل:** ۲۰۰ فروش روی دو صندوق، دو برگشت و بستن شیفت‌ها. حساب موجودی کالا = ارزش انبار، حساب صندوق = جمع نقد، همه‌ی اسناد متوازن.
  - پشتیبان‌گیری، بررسی، آزمون بازیابی واقعی و هشدارها.
  - ارائه‌ی رابط کاربری ساخته‌شده (SPA fallback، کش، جلوگیری از path traversal).
- Frontend: ۲۳ تست (افزوده: مقدار بدون float).
- End-to-end در مرورگر (Playwright، دستی):
  - صندوق‌دار: انتخاب صندوق، باز کردن شیفت، اسکن چند نوع بارکد، حذف ردیف با تأیید سرپرست، پرداخت نقد و چاپ فیش، کارت‌خوان آزمایشی با وضعیت نامشخص و استعلام، تعلیق و بازیابی، بستن شیفت.
  - مدیر: فاکتورها، برگشت، گزارش روزانه، شیفت‌ها، پروموشن‌ها، پشتیبان‌گیری.
  - تصاویر `30-*` تا `46-*`.
- آزمون بار: `backend/scripts/load_test.py`؛ نتایج در ADR-0013 و ROADMAP.
- آزموده‌نشده:
  - کارت‌خوان واقعی، چاپگر فیش واقعی، برچسب واقعی ترازو.
  - کارایی روی سخت‌افزار فروشگاه.
  - e2e در CI.
