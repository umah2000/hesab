# پروتکل همگام‌سازی و مدیریت تعارض (طراحی — پیاده‌سازی فاز ۸)

## ۱. چه چیزی آفلاین مجاز است
| عملیات | آفلاین صندوق | آفلاین موبایل | دلیل |
|---|:-:|:-:|---|
| فروش نقدی | ✓ | — | ادامه کار فروشگاه |
| فروش کارتی | ✓ فقط اگر Agent و کارت‌خوان در دسترس | — | کارت‌خوان مستقل از سرور |
| فروش نسیه | ✗ | — | نیازمند مانده لحظه‌ای مشتری |
| برگشت از فروش | ✗ | — | نیازمند فاکتور اصلی و مجوز |
| تخفیف بالای سقف | ✗ | — | نیازمند تأیید آنلاین |
| ثبت سفارش ویزیتور | — | ✓ | سفارش، نه سند مالی |
| سند حسابداری دستی، تعدیل موجودی | ✗ | ✗ | |

## ۲. داده پایه محلی (pull)
کالا، بارکد، قیمت، پروموشن فعال، کاربران مجاز همان صندوق (هش رمز محلی جدا)، سیاست‌ها. نسخه‌دار با `since=<server_cursor>`؛ اعتبار حداکثر N ساعت (تنظیمی)؛ پس از آن فروش آفلاین مسدود.

## ۳. عملیات (push)
هر عملیات در صف SQLite:
```json
{
  "operation_id": "uuid",          // = Idempotency-Key
  "device_id": "uuid", "branch_id": "uuid", "user_id": "uuid",
  "type": "sales.invoice.finalize",
  "local_time": "2026-10-11T10:15:00+03:30",
  "device_number": "B01-R02-000153",
  "base_data_version": 4821,        // نسخه قیمت/کالا هنگام ثبت
  "payload": { ... },
  "attempts": 0, "status": "pending", "last_error": null
}
```
- ارسال به ترتیب ایجاد؛ سرور `received_at` ثبت می‌کند.
- پاسخ سرور برای هر عملیات: `applied` · `duplicate` (قبلاً اعمال شده — موفق تلقی می‌شود) · `rejected` (با دلیل) · `conflict`.
- تلاش مجدد با backoff نمایی؛ وضعیت صف پس از خاموشی حفظ می‌شود (SQLite WAL).

## ۴. قواعد تعارض (هرگز Last-Write-Wins)
| تعارض | رفتار |
|---|---|
| قیمت در سرور تغییر کرده | فاکتور با **قیمت فروخته‌شده به مشتری** ثبت می‌شود (واقعیت رخ داده)؛ گزارش مغایرت قیمت |
| موجودی منفی شده | طبق سیاست: ثبت + هشدار + صف بررسی انباردار |
| کالا غیرفعال شده | ثبت + هشدار |
| کاربر غیرفعال شده | ثبت (فروش انجام شده) + رویداد امنیتی برای مدیر |
| شیفت در سرور بسته شده | ثبت در `sync_conflict`؛ حل دستی توسط سرپرست |
| تراکنش کارت بدون نتیجه قطعی | `ReconciliationRequired`؛ هرگز تکرار پرداخت خودکار |
| payload نامعتبر | `rejected` + گزارش؛ صف بقیه عملیات متوقف نمی‌شود |

قاعده کلی: **رخداد واقعی فروش رد نمی‌شود**؛ اثرات جانبی آن به صف بررسی انسانی می‌رود.

## ۵. شماره‌گذاری
`device_number` محلی روی فیش؛ `document_number` قطعی هنگام اعمال در سرور (ADR-0005).

## ۶. آزمون‌ها
قطع شبکه وسط ارسال؛ ارسال تکراری؛ خاموشی دستگاه با صف پر؛ تغییر قیمت هم‌زمان؛ دو صندوق آفلاین با موجودی محدود؛ ساعت اشتباه دستگاه.
