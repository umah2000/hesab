# ADR-0015: Device Agent — اتصال خروجی به سرور، صف کار، چاپ تصویری ESC/POS

**وضعیت:** پذیرفته · ۱۴۰۵/۰۷/۲۳ (پیاده‌شده در فاز ۶)

## زمینه
MASTER_PROMPT §۶.۲ یک API محلی روی `127.0.0.1` در نظر گرفته بود که مرورگر صندوق مستقیم آن را صدا بزند. فاز ۰ گفته بود محدودیت Chrome در دسترسی به localhost باید با نمونه‌ی اولیه آزموده شود. در این فاز آزموده شد:

- **آزمایش (Chromium 141، ۱۴۰۵/۰۷/۲۳):**
  - صفحه از `http://192.0.2.2:18766` (نشانی شبکه، HTTP) به `http://127.0.0.1:18765/health` درخواست فرستاد. سرویس محلی سرآیندهای CORS و `Access-Control-Allow-Private-Network` را هم برمی‌گرداند.
  - **مرورگر درخواست را رد کرد:** «The request client is not a secure context and the resource is in more-private address space `loopback`».
  - همان صفحه وقتی از خود `127.0.0.1` باز شد، درخواست رسید.
- **نتیجه:** پایلوت روی HTTP در شبکه داخلی اجرا می‌شود (ADR-0013). پس صندوق نمی‌تواند با API محلی کار کند. با HTTPS هم Chrome برای دسترسی به شبکه‌ی محلی اجازه‌ی کاربر می‌خواهد (Local Network Access) و رفتار آن بین نسخه‌ها تغییر می‌کند. دور زدن این کنترل‌ها ممنوع است (MASTER_PROMPT §۶.۲).

## تصمیم
1. **مرورگر هرگز مستقیم با Device Agent صحبت نمی‌کند.**
   - Agent خودش به سرور NEXTCAM وصل می‌شود (اتصال خروجی در شبکه داخلی) و حدود هر یک ثانیه از صف `device_job` کار می‌گیرد.
   - صندوق فقط از سرور می‌خواهد «فیش این فاکتور را چاپ کن».
   - مزیت دیگر: اگر مرورگر وسط کار بسته شود، کار و نتیجه‌اش روی سرور می‌ماند.
2. **API محلی فقط برای عیب‌یابی است:** `GET /status` روی `127.0.0.1`، بدون هیچ فرمان.
   - Host باید `127.0.0.1` یا `localhost` باشد (در برابر DNS rebinding).
   - هر درخواستی که سرآیند `Origin` دارد (یعنی از یک صفحه‌ی وب آمده) رد می‌شود.
   - هیچ سرآیند CORS فرستاده نمی‌شود. API برای اجرای فرمان دلخواه یا SQL وجود ندارد.
3. **جفت‌سازی و توکن دستگاه:**
   - مدیر (`devices.manage`) دستگاه را تعریف می‌کند و یک **کد یک‌بارمصرف ۸ نویسه‌ای** با اعتبار ۱۵ دقیقه می‌گیرد. فقط hash کد ذخیره می‌شود. نقطه‌ی جفت‌سازی به ۱۰ درخواست در دقیقه محدود است.
   - Agent کد را با یک **توکن دستگاه** تصادفی ۲۵۶ بیتی عوض می‌کند. فقط hash توکن در سرور ذخیره می‌شود. روی ویندوز، توکن با DPAPI و دامنه‌ی ماشین رمز می‌شود.
   - جفت‌سازی دوباره توکن قبلی را باطل می‌کند و «ابطال» دستگاه را فوراً قطع می‌کند.
   - این **انحراف آگاهانه از ADR-0004** است (Access ۱۵ دقیقه + Refresh). Agent یک سرویس ثابت در شبکه داخلی است، کاربر انسانی ندارد و ابطال فوری دارد؛ چرخش توکن کوتاه‌عمر پیچیدگی می‌افزاید بی‌آن‌که ریسک را کم کند. موبایل (فاز ۹) همان ADR-0004 را دنبال می‌کند.
4. **صف کار:**
   - **محتوا:** فیش، کشو یا صفحه‌ی آزمایشی. هر کار فقط **داده** است، هرگز بایت خام چاپگر یا کد.
   - **محاسبه:** متن، مبلغ، رقم فارسی، تومان یا ریال و تاریخ شمسی را سرور آماده می‌کند. Agent هیچ مبلغی را حساب نمی‌کند.
   - **وضعیت‌ها:** `queued` ← `sent` ← `done` | `failed`.
   - **انقضا:** کاری که ۲ دقیقه در صف بماند `expired` می‌شود و **هرگز دیرتر چاپ نمی‌شود**. کار `sent` بی‌پاسخ هم منقضی می‌شود و صندوق‌دار کاغذ را بررسی می‌کند.
   - **بدون تکرار خودکار:** هیچ کاری خودکار دوباره فرستاده نمی‌شود، چون فیش دوم یا باز شدن دوباره‌ی کشو بدتر از نبودن آن است. Agent هر شناسه‌ی کار را حداکثر یک بار اجرا می‌کند.
   - **صندوق‌دار:** برای هر کار نتیجه‌ی قطعی می‌بیند («فیش چاپ شد» یا خطا). در هر حالتِ غیرموفق، «چاپ با مرورگر» پیشنهاد می‌شود.
5. **کشوی پول:**
   - با **اولین کار** فاکتور نقدی (فروش یا استرداد نقدی) باز می‌شود. اگر چاپ خودکار خاموش باشد، کار «فقط کشو» فرستاده می‌شود.
   - چاپ مجدد کشو را باز نمی‌کند.
   - باز کردن بدون فروش فقط با `sales.drawer.open` (سرپرست و مدیر) و با **علت** ممکن است و ممیزی می‌شود.
6. **چاپ فیش به‌صورت تصویر (raster):**
   - بیشتر چاپگرهای حرارتی صفحه‌کد قابل‌اعتماد فارسی ندارند. فیش با Pillow و موتور RAQM (HarfBuzz/FriBiDi، همراه wheel) و فونت Vazirmatn (OFL) به تصویر تک‌رنگ ۵۷۶ یا ۳۸۴ نقطه تبدیل می‌شود.
   - تصویر با دستور `GS v 0` در نوارهای ۲۵۵ ردیفی فرستاده می‌شود.
   - فقط دستورهای پایه‌ی مستند ESC/POS به کار می‌رود: `ESC @`، `ESC p` (کشو)، `ESC d` و `GS V` (برش).
   - **سازگاری هر مدل** باید روی خود دستگاه اثبات شود ([رجیستری سازگاری](../../hardware/compatibility-registry.md)).
7. **راه‌های اتصال چاپگر:**
   - TCP خام (معمولاً درگاه ۹۱۰۰)
   - صف چاپ ویندوز در حالت RAW برای چاپگر USB نصب‌شده در ویندوز (`pywin32`)
   - درگاه سریال (`pyserial`)
8. **نمایشگر مشتری:** پنجره‌ی دوم مرورگر روی مانیتور دوم صندوق. صفحه‌ی صندوق فقط اقلام، مبلغ قابل پرداخت و باقی‌مانده را از طریق `BroadcastChannel` هم‌مبدأ به آن می‌فرستد و Agent لازم نیست. نمایشگرهای قطبی (VFD سریال) تا مشخص شدن مدل ساخته نمی‌شوند.
9. **بارکدخوان HID** همچنان مستقیم در مرورگر کار می‌کند. اگر زبان ویندوز فارسی باشد و جست‌وجوی کد ناموفق شود، کلیدهای حرفیِ بدون Shift که در دو چیدمان رایج یکسان‌اند به لاتین برگردانده می‌شوند و هشدار «زبان صفحه‌کلید را انگلیسی کنید» نمایش داده می‌شود. این نگاشت باید با اسکنر واقعی تأیید شود.
10. **کارت‌خوان از طریق Agent ساخته نشد.** تا مشخص شدن PSP و دریافت مستند رسمی (Q1)، فقط ماشین وضعیت و Mock سمت سرور (فاز ۴) باقی است. قرارداد Adapter بدون تغییر است.
11. **چاپگر لیبل** در این فاز به Agent منتقل نشد. چاپ برچسب قفسه همچنان از مرورگر است (فاز ۳). زبان دستوری چاپگرهای لیبل (TSPL/ZPL/EPL…) به مدل بستگی دارد و بدون مدل مشخص ساخته نمی‌شود (Q19).

## پیامدها
- **ساختار:** نصب Agent فقط به دسترسی خروجی صندوق به سرور نیاز دارد. روی صندوق درگاه ورودی باز نمی‌شود، فقط `127.0.0.1` برای عیب‌یابی.
- **تأخیر:** هر چاپ حداکثر حدود ۱ ثانیه تأخیر صف دارد.
- **بار:** هر Agent در هر ثانیه یک درخواست سبک می‌فرستد (۷ صندوق یعنی حدود ۷ درخواست در ثانیه). آخرین زمان ارتباط حداکثر هر ۵ ثانیه یک بار نوشته می‌شود.
- **محدودیت:** هیچ‌یک از این‌ها روی چاپگر، کشو یا ویندوز واقعی آزموده نشده است.
  - آزمون‌ها در سطح پروتکل‌اند: بایت‌های ESC/POS که یک چاپگر شبکه‌ی جعلی دریافت کرد دوباره به تصویر تبدیل و بررسی شد.
  - CI ویندوز (DPAPI و import سرویس) تعریف شده، ولی تا اجرای اولین PR نتیجه ندارد.
