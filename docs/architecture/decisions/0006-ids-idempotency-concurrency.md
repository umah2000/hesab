# ADR-0006: شناسه‌ها، Idempotency و همزمانی

**وضعیت:** پذیرفته · ۱۴۰۵/۰۷/۱۹ (پیاده‌سازی پایه: `backend/app/core/db.py`)

## تصمیم
- **کلید اصلی همه جداول تجاری:** `UNIQUEIDENTIFIER` که کلاینت (POS، موبایل، Agent) می‌تواند خودش تولید کند. برای کاهش fragmentation در جداول پرحجم، Index خوشه‌ای روی ستون ترتیبی (`seq BIGINT IDENTITY`) یا تاریخ قرار می‌گیرد و PK غیرخوشه‌ای است.
- **Idempotency-Key:** همه درخواست‌های ایجادکننده سند (فاکتور، دریافت، پرداخت، سند، گردش انبار) هدر `Idempotency-Key` (UUID) دارند. جدول `idempotency_record (key, user_id, endpoint, request_hash, response, created_at)`؛ تکرار همان کلید با همان بدنه ← پاسخ ذخیره‌شده؛ با بدنه متفاوت ← 409.
- **همزمانی خوش‌بینانه:** ستون `row_version ROWVERSION` در جداول قابل ویرایش؛ به‌روزرسانی با نسخه قدیمی ← 409.
- **ستون‌های پایه:** `created_at`، `updated_at` (UTC)، `created_by`، `updated_by`؛ و `branch_id` در همه جداول عملیاتی از روز اول.

## پیامدها
+ آفلاین و همگام‌سازی بدون تغییر ساختار جداول.
+ دوبار کلیک یا retry شبکه سند تکراری نمی‌سازد.
