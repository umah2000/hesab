# ارزیابی امنیتی — فاز ۱۰

**تاریخ:** ۱۴۰۵/۰۷/۲۷ (2026-10-19). **نسخه:** شاخه‌ی فاز ۱۰ (migration 0013).

> این یک **خودارزیابی** توسط تیم توسعه است، نه آزمون نفوذ مستقل.
> - پیش از استفاده‌ی گسترده، یا اگر داده‌ی پرداخت کارتی مستقیم وارد سیستم شود، یک آزمون نفوذ مستقل توصیه می‌شود.
> - آنچه این‌جا «آزموده شد» آمده، واقعاً اجرا شده است.

## ۱. دارایی‌ها و مهاجم‌ها
**دارایی‌ها:**
- اسناد مالی و فروش (یکپارچگی).
- موجودی.
- اطلاعات طرف‌حساب‌ها (شماره تماس، نشانی، مانده).
- حساب‌های کاربری.
- توکن دستگاه‌ها (Agent و اپ ویزیتور).
- پشتیبان‌های دیتابیس.

| مهاجم | دسترسی | نگرانی اصلی |
|---|---|---|
| کاربر داخلی با نقش محدود (صندوق‌دار) | حساب معتبر | کارهای بیرون از نقش؛ دستکاری قیمت، تخفیف یا برگشت؛ دیدن شعبه‌ی دیگر |
| دستگاه دیگر در شبکه‌ی فروشگاه | شبکه | شنود رمز یا کوکی؛ CSRF از صفحه‌ی دیگر؛ دسترسی مستقیم به SQL Server |
| مهاجم اینترنتی (فقط اگر Q21 فعال شود) | مسیرهای اپ ویزیتور | حدس رمز؛ سوءاستفاده از توکن؛ دسترسی به پنل |
| سرقت گوشی ویزیتور یا رایانه‌ی صندوق | دستگاه | استفاده از توکن ذخیره‌شده |
| سرقت فایل پشتیبان | فایل | خواندن کل داده |

### ۳.۲ کاوش‌های حمله (خودکار، روی SQL Server واقعی)
`backend/tests/test_security_probes.py` — ۶ تست، همه موفق:

| کاوش | انتظار | نتیجه |
|---|---|---|
| SQL injection در جست‌وجو (`' OR 1=1 --`) | تطبیق متنی؛ صفر نتیجه | ✅ |
| SQL injection در بارکد (`'; DROP TABLE item;--`) | 404؛ جدول سالم | ✅ |
| نام کالا با `<img onerror>` | ذخیره و بازگشت به‌صورت متن JSON | ✅ |
| افزودن `number`، `grand_total`، `status` یا `unit_price` به فاکتور | 400؛ پذیرفته نمی‌شود، نادیده هم گرفته نمی‌شود | ✅ |
| مبلغ به‌صورت عدد اعشاری JSON | 400 | ✅ |
| درخواست تغییر بدون سرآیند CSRF | `csrf_failed` | ✅ |
| بدنه‌ی ۳MB | 413 | ✅ |
| خواندن فاکتور، وضعیت صندوق یا برگشت از شعبه‌ی دیگر با id درست | 404؛ در فهرست هم نیست | ✅ |
| کوکی پس از خروج (replay) | 401 | ✅ |
| کاربر ناموجود در برابر رمز غلط | پیام یکسان | ✅ |
| پاسخ ورود | بدون هش رمز | ✅ |
| خطای داخلی با متن شبیه connection string | 500 عمومی با شناسه‌ی رخداد؛ بدون متن خطا | ✅ |
| `/../app/__init__.py` و `%2e%2e/etc/passwd` | خارج از پوشه‌ی build چیزی برنمی‌گردد | ✅ |
| سرآیندهای امنیتی روی صفحه و API | CSP، HSTS، no-store و… | ✅ |

تست‌های پیشین که همچنان اجرا می‌شوند:
- **ماتریس مجوز** (`test_security_matrix.py`): هر endpoint بدون ورود → 401 و بدون مجوز → 403، به‌جز فهرست صریح مسیرهای عمومی.
- **دستکاری سند قطعی** مستقیم در دیتابیس.
- **استفاده‌ی دوباره از refresh token**.
- **توکن Bearer** بیرون از مسیرهای اپ.
- **قفل حساب**.

کل مجموعه‌ی backend: **۱۲۸ تست موفق** روی SQL Server 2019.

### ۳.۳ موارد bandit
- **B104 (متوسط) — گوش دادن روی `0.0.0.0`:** عمدی است، چون سرور شبکه‌ی داخلی است. با HTTPS، `NEXTCAM_HOST=127.0.0.1` توصیه می‌شود تا فقط Caddy به برنامه برسد.
- **B101 (کم، ۲۷ مورد) — `assert`:** همه برای باریک کردن نوع (`x is not None`) پس از بررسی قبلی‌اند. هیچ‌کدام کنترل امنیتی نیست:
  - با `python -O` حذف شدن آن‌ها مجوزی را دور نمی‌زند؛ در بدترین حالت خطای 500 می‌دهد.
  - مورد `permissions.py` یک بررسی سازگاری هنگام شروع است: نقشی که به مجوز ناشناخته اشاره کند.

### ۳.۴ مرورگر
- اجرای برنامه‌ی ساخته‌شده با `python -m app.serve`، یک بار مستقیم و یک بار پشت Caddy با HTTPS.
- ۱۲ صفحه در Chromium باز شد (داشبورد، صندوق، فاکتورها، کالاها، برچسب، اسناد، گزارش‌ها، سفارش‌های ویزیتور، دستگاه‌ها، تنظیمات، نمایشگر مشتری): **بدون هیچ نقض CSP**.
- خروجی Excel و چاپ کار کرد.
- پشت HTTPS، کوکی‌ها `Secure` بودند و `X-Forwarded-For` جعلی ثبت نشد.

## ۴. محدودیت‌ها و ریسک‌های باقی‌مانده
| مورد | وضعیت |
|---|---|
| آزمون نفوذ مستقل | انجام نشده. پیشنهاد: پیش از اتصال اپ ویزیتور به اینترنت (Q21). |
| HTTPS روی ویندوز واقعی | فقط روی لینوکس آزموده شده است ([https.md](../install/https.md)). |
| محدودیت تلاش ورود در حافظه‌ی همان پردازه | با یک پردازه‌ی waitress کافی است؛ با چند پردازه باید ذخیره‌ی مشترک داشته باشد. |
| SQL Server | باید فقط روی همان ماشین یا شبکه‌ی جدا در دسترس باشد؛ پورت 1433 بسته (راهنمای نصب). رمزنگاری اتصال برنامه به SQL Server روی همان ماشین فعال نیست (`TrustServerCertificate`). |
| پشتیبان | تا تکمیل پشتیبان رمزنگاری‌شده‌ی فاز ۱۰، فایل `.bak` رمزنگاری نشده است. |
| رمز کاربران | سیاست ساده: حداقل ۸ نویسه، حرف و عدد، مخالف نام کاربری. احراز دومرحله‌ای ساخته نشده. |
| کلید CA محلی Caddy | هر کس آن را داشته باشد، برای شبکه گواهی معتبر می‌سازد؛ دسترسی فقط برای مدیر سیستم. |
| گوشی ویزیتور روت‌شده | Keystore را می‌توان دور زد؛ نشست با «ابطال نشست‌ها»ی کاربر قطع می‌شود. |
| عدم انکار (non-repudiation) | رویدادنگار با شماره‌ی ترتیبی (seq) هست، اما زنجیره‌ی هش یا امضای رمزنگاری ندارد. |
