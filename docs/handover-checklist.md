# چک‌لیست تحویل به فروشگاه

برای هر فروشگاه یک نسخه پر و امضا شود. هر مورد: ✅ انجام شد · ⚠️ با توضیح · ⛔ انجام نشد (با دلیل و تاریخ پیگیری).

## ۱. سرور و نصب
- [ ] **بسته‌ی انتشار:** چکیده‌ی SHA256 با فایل `.sha256` یکسان است.
- [ ] **SQL Server:** نسخه‌ی 2019 یا بالاتر با آخرین CU. پورت 1433 روی شبکه **بسته** است.
- [ ] **حافظه:** سقف حافظه‌ی SQL Server تنظیم شده است (روی سرور ۴GB).
- [ ] **کاربر دیتابیس:** با `create-database.sql` ساخته شده و رمز قوی دارد. رمز فقط در `config\.env` است.
- [ ] **`install.ps1`** بدون خطا اجرا شده است.
- [ ] **`check-integrity`:** هر چهار مورد ok است.
- [ ] **کارهای زمان‌بندی‌شده:** `NEXTCAM Server`، `Backup` و `Restore Test` فعال‌اند.
- [ ] **راه‌اندازی دوباره:** سرور یک بار ری‌استارت شد و برنامه خودکار بالا آمد.
- [ ] **دسترسی `config\.env`:** فقط Administrators و SYSTEM (بررسی با `icacls`).

## ۲. شبکه و HTTPS
- [ ] **Caddy:** با گواهی داخلی اجرا می‌شود. `https://<نام سرور>` باز می‌شود و `http` به `https` منتقل می‌شود.
- [ ] **گواهی ریشه:** روی **همه‌ی** صندوق‌ها و رایانه‌های مدیریتی نصب شده است.
- [ ] **امنیت برنامه:** `NEXTCAM_HOST=127.0.0.1` و `COOKIE_SECURE=true` است، و پورت 8080 از شبکه بسته است.
- [ ] **فایروال:** فقط پروفایل Private؛ Wi-Fi مهمان به شبکه‌ی صندوق‌ها دسترسی ندارد.
- [ ] **اپ ویزیتور (در صورت استفاده):** دامنه و گواهی عمومی دارد و فقط مسیرهای اپ از اینترنت باز است (Q21).

## ۳. پشتیبان‌گیری (ریسک R2)
- [ ] **مقصد دوم** (USB ثابت، NAS یا پوشه‌ی ابری) تنظیم شده است.
- [ ] **`flask backup`** دو خط «backup ok» و «encrypted copy ok» چاپ کرد.
- [ ] **کلید پشتیبان** روی کاغذ یا در مدیر رمز مالک، **بیرون از سرور**، ثبت شد. محل نگهداری: …………
- [ ] **آزمون بازیابی** (`backup-restore-test`) موفق بود.
- [ ] **بازیابی روی رایانه‌ی دیگر:** یک بار با فایل مقصد دوم و کلید نگهداری‌شده انجام شد.
- [ ] **هشدار داشبورد:** «پشتیبان‌گیری نیاز به توجه دارد» نمایش داده نمی‌شود.

## ۴. صندوق‌ها
برای هر صندوق یک سطر:

| صندوق | Agent جفت شد | فیش آزمایشی فارسی | کشو | بارکدخوان (HID + Enter) | برچسب ترازو | فروش آفلاین آزموده شد |
|---|---|---|---|---|---|---|
| | | | | | | |

- [ ] **کارت‌خوان:** روش فعلی (ورود دستی شماره‌ی پیگیری) به صندوق‌داران آموزش داده شد. اتصال یکپارچه منتظر مستند PSP است (Q1).
- [ ] **فیش:** نمونه‌ی فیش با سربرگ و پانویس فروشگاه تأیید مالک را گرفت (Q16).
- [ ] **ترازو:** قالب بارکد با **چند برچسب واقعی** آزموده شد (Q3/Q16).
- [ ] **سخت‌افزار:** چاپگر و کشو با مدل واقعی آزموده شدند (Q20).

## ۵. داده‌ی اولیه
- [ ] **کالاها:** بارکد، قیمت و وضعیت مالیات (معاف یا مشمول) وارد و نمونه‌برداری شد.
- [ ] **موجودی اول دوره** ثبت و با شمارش فیزیکی مقایسه شد.
- [ ] **طرف‌حساب‌ها:** مانده‌ی اول دوره و سقف اعتبار مشتریان نسیه ثبت شد.
- [ ] **حسابداری:** سال مالی جاری باز است و قواعد ثبت را حسابدار فروشگاه تأیید کرد.
- [ ] **بانک:** حساب‌های بانک و صندوق‌های خزانه تعریف شدند.

## ۶. کاربران و آموزش
- [ ] **حساب پیش‌فرض:** رمز مدیر سیستم عوض شده است و حساب مشترک وجود ندارد.
- [ ] **حساب فردی:** هر نفر حساب خودش را با نقش و محدوده‌ی شعبه‌ی درست دارد.
- [ ] **آموزش با راهنمای `docs/user`:**
  - صندوق‌داران: شیفت، فروش، پرداخت، کارت نامشخص، بستن شیفت؛
  - سرپرست: تأیید و برگشت؛
  - انباردار؛
  - حسابدار؛
  - مدیر.
- [ ] **مسیر گزارش مشکل** گفته شد: شناسه‌ی رخداد در پیام خطا، و تماس با پشتیبانی.
